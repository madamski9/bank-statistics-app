# Android parity

The goal of the [Android parity](https://github.com/madamski9/bank-statistics-app/milestone/1) milestone is that Android works exactly as iOS works in release 1.0.2. Nothing beyond that is built here. If a task needs something iOS does not have, open a separate issue instead of building it.

GitHub is the source of truth for the status of each issue. This document defines the order and the rules.

## Decisions to follow

- [ADR 0004](adr/0004-use-expo-with-native-platform-modules.md): Expo development builds with native Kotlin modules. Expo Go is not supported.
- [ADR 0005](adr/0005-share-parser-rules-across-native-interpreters.md): Kotlin interprets the same rule bundle and examples as Swift.
- [ADR 0015](adr/0015-use-a-shared-encrypted-local-outbox.md): SQLCipher outbox with the key in Android Keystore.
- [ADR 0019](adr/0019-capture-android-card-payments-from-google-wallet.md): card payments come from Google Wallet, and only cards of Supported Banks are captured.
- [ADR 0020](adr/0020-build-the-android-widget-natively-with-glance.md): the widget is Kotlin and Jetpack Glance.
- [ADR 0021](adr/0021-read-android-pdf-statements-with-pdfbox.md): PDF text comes from PdfBox-Android behind `extractPdfText`.
- Recents preview: on Android 13+ use `setRecentsScreenshotEnabled(false)`. On Android 7–12 use `FLAG_SECURE` only while the app lock is enabled.
- Background capture: no foreground service or permanent notification. On disconnect the listener requests a rebind. Battery optimization is raised only when the system actually restricts the app.

## Where code goes

- Kotlin lives in `packages/ingestion-native/android`, next to `ios/`, behind the TypeScript API in `packages/ingestion-native/src/index.ts`.
- Manifest entries, services and permissions are added through the config plugin in `packages/ingestion-native/plugin`. `mobile/android` is generated by prebuild and never committed.
- Bank rules, the allowlist and examples live in `packages/parser-rules`.
- Screens and hooks stay in `mobile/src/features/<area>/<feature>`, as described in `mobile/src/features/README.md`. Android-specific UI goes into the feature it belongs to, not into a global folder.
- Feature folders that each issue touches:
  - Sign-in: `auth/sign-in`
  - Onboarding: `onboarding/steps` and `onboarding/shortcut-setup`
  - Capture Health: `settings/capture-health`
  - Privacy and app lock: `settings/privacy`
  - Statement import: `settings/statement-import`
  - Local storage: `data/local-storage`
  - Widget: `widgets`
  - Captured spending on Overview: `home/state`

## How to work on an issue

1. Confirm that every issue it is blocked by is closed, then read the issue, the ADRs above and the Expo 57 docs for any API you touch.
2. Work on one branch per issue, named in the existing style (`feat/…`, `fix/…`, `chore/…`), and open one pull request against `main` that closes the issue.
3. Match the iOS behaviour of the same feature. Read the Swift implementation and the shared TypeScript before writing Kotlin.
4. Treat the rule bundle, the examples and the TypeScript API of `ingestion-native` as shared contracts. A change to them must keep the TypeScript reference, Swift and Kotlin interpreters in agreement. Any change that alters iOS behaviour must be agreed with the iOS owner.
5. Never store or send raw notification text, and add only sanitized samples to the repository.
6. Before opening the pull request, run `bun run typecheck`, `bun test` and `bun run lint`, then build and exercise the change with `./run.sh android` on the `BankStats_API36` emulator. Verify capture, battery and lock behaviour on a physical Samsung device.
7. Tick the acceptance criteria in the issue as they are met. Report anything left unmet in the pull request instead of closing the issue.
