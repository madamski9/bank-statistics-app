# Convert on the device with centrally cached NBP rates

This refines ADR 0012. Convex still obtains and caches NBP table A (and, failing that, table B) mid rates, but it answers only "currency and calendar date" requests and never receives the amount being converted. The device multiplies the original minor units by the decimal rate with integer arithmetic and stores the Exchange Rate Snapshot (rate, effective date, table number) and the Reporting Amount on the transaction itself, which then synchronizes like any other field. A rate for today is not cached until NBP publishes it, a weekend or holiday uses the latest earlier table, and an unavailable NBP leaves the transaction out of totals until a later retry. Keeping the amount on the device lets conversion work in this-phone-only mode without sending financial data anywhere, and storing the snapshot on the transaction keeps historical totals stable on every device.
